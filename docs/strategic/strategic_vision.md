# 🎯 Codegen 战略业务愿景 (Strategic Vision)

## 1. 北极星目标
用确定性的静态工具，为不确定性的 LLM 划定不可逾越的“脚手架”和“护栏”。

## 2. 域划分 (Domain Classification)

### 核心域 (Core Domain)
**DomainDefinition (领域定义上下文)**
- 核心价值：维护 `codegen.yaml` 作为整个系统的**单一事实来源 (SSOT)**，承载所有领域模型、业务规则与架构约束的唯一权威定义。
- 战略重要性：★★★★★ 是整个系统的核心竞争力所在，所有其他上下文均围绕该域展开。

### 支撑域 (Supporting Domains)
1. **PythonGen (Python 代码生成上下文)**
   - 核心价值：将 DomainDefinition 输出的模型高保真转换为可执行的 Python 代码，实现 AST 级别的双向解析与渲染。
   - 战略重要性：★★★★ 是当前阶段的核心交付能力。

2. **Orchestration (编排上下文)**
   - 核心价值：调度各个上下文的业务流转，实现 CLI/MCP 入口到各个子域的命令路由。
   - 战略重要性：★★★ 是连接用户交互与核心能力的枢纽。

### 通用域 (Generic Domains)
**Shared Kernel (共享内核)**
- 核心价值：提供跨上下文通用的工具类、基础原语与通用抽象，避免重复建设。
- 战略重要性：★★★ 所有上下文的公共依赖，保证系统一致性。

## 3. 核心设计原则
1. **基础设施下沉**：核心领域层绝对纯净，所有底层操作（AST操作、文件读写）必须通过端口隔离。
2. **状态单一化**：Markdown 设计文档仅用于高维业务决策，不维护结构化字段，彻底消灭双写灾难。
3. **Agentic 友好**：架构设计与模块拆分必须充分考虑 LLM 的上下文窗口大小与任务分解能力。
