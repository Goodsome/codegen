# 🐍 PythonGen 领域业务叙事

## 🎯 业务愿景
PythonGen 是 Codegen 系统的核心支撑域，承担着“高保真 Python 代码生成与双向工程”的核心使命。它的目标是提供一套从领域模型到 Python 代码的无损转换能力，以及从现有 Python 代码逆向更新领域模型的反向工程能力，实现“蓝图即代码，代码即蓝图”的闭环开发体验。

## 🏗️ 核心价值主张
1. **高保真代码生成**：严格遵循 Python 语法规范与项目编码风格，生成符合生产级质量的代码
2. **双向工程能力**：支持正向（蓝图→代码）和反向（代码→蓝图）的双向同步，保持蓝图与代码的一致性
3. **AST 级操作**：基于 Python 抽象语法树（AST）实现代码操作，避免字符串拼接带来的语法错误
4. **质量内置**：自动集成代码格式化、类型检查等质量保障环节，生成的代码直接符合项目规范

## 📋 核心业务流程

### 1. 正向代码生成流程
```
接收 DomainDefinition 输出的模型转换结果 → 转换为 PythonGen 内部的代码结构规约 → 生成 Python AST 节点 → 渲染为源代码文件 → 执行代码格式化与质量检查 → 写入文件系统
```
**业务规则**：
- 生成的代码必须完全符合 Python 3.13 语法规范
- 必须保留所有领域模型中的业务规则与约束
- 生成的代码必须通过 basedpyright 严格类型检查
- 代码风格必须符合 black 格式化规范

### 2. 反向工程流程
```
读取现有 Python 代码文件 → 解析为 Python AST 节点 → 转换为 PythonGen 内部的代码结构规约 → 逆向映射为 DomainDefinition 领域模型 → 更新 Blueprint 聚合根
```
**业务规则**：
- 反向解析必须尽可能保留原始代码的业务语义
- 无法识别的代码片段必须作为 RawCodeSpec 保留，不得丢失
- 必须支持增量更新，不会覆盖用户手动编写的合法代码

### 3. 代码合并流程
```
接收新生成的代码结构与现有代码结构 → 执行语义级别的合并操作 → 生成合并后的代码结构 → 渲染为源代码文件
```
**业务规则**：
- 必须保留用户手动添加的自定义代码
- 冲突检测必须精准，不得无理由覆盖用户代码
- 合并结果必须保持语法合法与语义一致性
