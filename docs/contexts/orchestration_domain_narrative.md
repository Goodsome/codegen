# 🎼 Orchestration 领域业务叙事

## 🎯 业务愿景
Orchestration 是 Codegen 系统的核心支撑域，承担着"系统入口与流程编排"的核心使命。它的目标是提供统一的对外访问入口，协调跨上下文的复杂业务流程，屏蔽底层领域模型与代码生成的复杂度，为用户提供简洁、一致的使用体验。

## 🏗️ 核心价值主张
1. **统一入口**：提供 CLI、MCP 等多种访问方式，所有外部请求必须经过本上下文路由
2. **流程编排**：协调 DomainDefinition、PythonGen 等多个上下文的能力，实现复杂业务流程
3. **结果聚合**：统一收集、聚合各个上下文的执行结果，返回标准化的响应格式
4. **错误统一处理**：集中处理所有业务异常，提供统一的错误信息与用户提示

## 📋 核心业务流程

### 1. 正向代码生成流程（build 命令）
```
用户执行 build 命令 → 本上下文接收命令参数 → 调用 DomainDefinition 加载并验证 Blueprint → 调用 DomainDefinition 转换为 PackageSpec → 调用 PythonGen 生成代码文件 → 聚合生成结果 → 返回 BuildResult 给用户
```
**业务规则**：
- 支持增量生成，只修改发生变化的文件
- 支持选择性生成指定的上下文或模块
- 生成过程中必须实时输出进度信息
- 必须提供详细的生成统计与差异报告

### 2. 反向工程流程（reverse 命令）
```
用户执行 reverse 命令 → 本上下文接收代码目录路径 → 调用 PythonGen 解析现有代码为 PackageSpec → 调用 DomainDefinition 转换为 Blueprint → 持久化 Blueprint 到 codegen.yaml 文件 → 返回结果给用户
```
**业务规则**：
- 必须保留现有代码中的所有业务语义
- 无法识别的代码片段必须标记并提示用户
- 生成的 Blueprint 必须符合 schema 规范
- 必须提供详细的解析报告与警告信息

### 3. MCP 工具请求处理流程
```
用户通过 MCP 发送工具请求 → 本上下文接收请求参数 → 参数合法性校验 → 路由到对应的应用层用例 → 协调各个上下文执行业务逻辑 → 聚合执行结果 → 返回标准化的 MCP 响应
```
**业务规则**：
- 所有 MCP 工具必须遵循统一的参数与响应格式
- 必须提供详细的错误信息与帮助提示
- 支持异步请求与进度回调
- 必须符合 MCP 协议规范

### 4. 跨上下文事务协调流程
```
接收跨上下文的业务请求 → 定义事务边界与补偿逻辑 → 依次调用各个上下文的服务 → 任意步骤失败则执行补偿操作 → 最终返回统一的事务结果
```
**业务规则**：
- 跨上下文操作必须保证最终一致性
- 失败操作必须提供明确的回滚机制
- 必须记录完整的操作日志用于排查问题
- 必须提供事务执行的详细报告
