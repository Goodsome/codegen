# 📖 DomainDefinition 通用语言与规约

## 🔤 核心名词解释

### 1. Blueprint (蓝图)
- **定义**：整个代码生成系统的唯一聚合根，代表完整的项目定义
- **业务含义**：是所有代码生成操作的唯一输入来源，包含了项目的所有领域模型、上下文划分、基础设施配置等信息
- **不变量**：
  - 必须有且仅有一个 name 属性
  - 至少包含一个 BoundedContext 定义
  - 所有上下文名称必须全局唯一

### 2. BoundedContext (限界上下文)
- **定义**：领域边界的划分单元，代表一个独立的业务领域或能力单元
- **业务含义**：将大型复杂的领域模型拆分为多个独立的小模型，每个上下文内的模型具有高度内聚性，上下文之间通过明确的接口进行交互
- **不变量**：
  - 每个上下文必须有全局唯一的名称
  - 上下文内的领域概念名称必须唯一
  - 上下文之间不得有循环依赖

### 3. DomainConcept (领域概念)
- **定义**：上下文内所有领域元素的抽象基类，包括实体、值对象、聚合根、领域服务等
- **业务含义**：统一了所有领域元素的基础结构与行为规范
- **不变量**：
  - 必须有 name 和 description 属性
  - 属性列表与行为列表必须独立维护
  - 名称必须符合 PascalCase 命名规范

### 4. AttributeSpec (属性规约)
- **定义**：领域概念的属性定义规范
- **业务含义**：描述领域概念的静态特征，包括类型、默认值、约束等信息
- **不变量**：
  - 属性名称必须符合 snake_case 命名规范
  - 类型必须是已定义的领域类型或基础类型
  - 同一领域概念下的属性名称必须唯一

### 5. MethodSpec (行为规约)
- **定义**：领域概念的行为定义规范
- **业务含义**：描述领域概念的动态行为，包括输入参数、输出结果、业务规则等信息
- **不变量**：
  - 方法名称必须符合 snake_case 命名规范
  - 输入参数与输出类型必须是已定义的类型
  - 同一领域概念下的方法签名必须唯一

### 6. AttributeSpecList (属性规约列表)
- **定义**：属性规约的集合容器
- **业务含义**：提供属性的增删改查、类型转换等批量操作能力
- **不变量**：
  - 列表内的属性名称必须唯一
  - 所有操作必须保持列表的一致性

### 7. MethodSpecList (行为规约列表)
- **定义**：行为规约的集合容器
- **业务含义**：提供行为的增删改查、类型转换等批量操作能力
- **不变量**：
  - 列表内的方法签名必须唯一
  - 所有操作必须保持列表的一致性

## 📏 实体不变量规则

### Blueprint 聚合根不变量
```gherkin
Given 一个 Blueprint 实例
When 添加新的 BoundedContext
Then 该上下文的名称必须在全局范围内唯一
    且 上下文内部的所有领域概念名称必须唯一
```

```gherkin
Given 一个 Blueprint 实例
When 执行更新操作
Then 必须保持所有实体的关联关系完整性
    且 不能产生孤立的领域概念引用
```

### DomainConcept 不变量
```gherkin
Given 一个 DomainConcept 实例
When 添加新的 AttributeSpec
Then 属性名称必须在当前概念内唯一
    且 属性类型必须是已定义的有效类型
```

```gherkin
Given 一个 DomainConcept 实例
When 添加新的 MethodSpec
Then 方法签名必须在当前概念内唯一
    且 参数与返回值类型必须是已定义的有效类型
```

## 🎯 业务约束规则

### 命名约束
```gherkin
Given 任何领域元素的名称定义
When 进行合法性校验
Then
  - 上下文名称：PascalCase，首字母大写，不包含特殊字符
  - 领域概念名称：PascalCase，首字母大写，不包含特殊字符
  - 属性名称：snake_case，全小写，下划线分隔
  - 方法名称：snake_case，全小写，下划线分隔
  - 枚举值名称：UPPER_SNAKE_CASE，全大写，下划线分隔
```

### 类型系统约束
```gherkin
Given 任何类型引用
When 进行合法性校验
Then
  - 基础类型必须是系统预定义的类型（string, int, float, bool 等）
  - 自定义类型必须是当前上下文内已定义的领域概念
  - 容器类型（list, dict, optional）必须指定有效的泛型参数
```

### 变更操作约束
```gherkin
Given 任何变更操作请求
When 执行操作
Then
  - 必须通过命令式接口执行，禁止直接修改领域实体状态
  - 操作执行前必须完成全量业务规则校验
  - 操作失败必须回滚到之前的状态，不得产生中间无效状态
```

## 🔒 访问约束
- 所有领域实体的状态只能通过本上下文的应用服务接口修改
- 跨上下文访问只能使用不可变的 DTO 对象，不得直接传递领域实体引用
- 蓝图的持久化操作只能由本上下文的基础设施层执行
